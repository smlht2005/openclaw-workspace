# Token 使用報告格式設計

## 報告結構

```markdown
📊 Token 使用報告 - {日期}

### 📈 數據摘要
| 項目 | 數值 |
|------|------|
| 模型 | MiniMax-M2.5 |
| 執行時間 | 09:00 (台北) |
| Input | {N} tokens |
| Output | {N} tokens |
| Total | {N} tokens |
| Context | {N}% |
| 備註 | - |

### 🔥 關注重點
{1-2 句精簡描述}

### 💡 建議
- {建議 1}
- {建議 2}
```

---

## 範例：正常情況

```markdown
📊 Token 使用報告 - 2026-02-16

### 📈 數據摘要
| 項目 | 數值 |
|------|------|
| 模型 | MiniMax-M2.5 |
| 執行時間 | 09:00 (台北) |
| Input | 45,230 tokens |
| Output | 8,120 tokens |
| Total | 53,350 tokens |
| Context | 45% |
| 備註 | - |

### 💡 建議
- ✅ 使用量正常，維持現狀
- 下午可跑深度任務
```

---

## 範例：Context > 80%（警告）

```markdown
⚠️ Token 使用報告 - 2026-02-16

### 📈 數據摘要
| 項目 | 數值 |
|------|------|
| 模型 | MiniMax-M2.5 |
| 執行時間 | 21:00 (台北) |
| Input | 285,000 tokens |
| Output | 12,500 tokens |
| Total | 297,500 tokens |
| Context | **100%** 🔴 |
| 備註 | 建議 /new |

### 🔥 關注重點
Context 滿載，執行效率差，建議重置

### 💡 建議
- ⚠️ 馬上用 `/new` 開新 session
- 檢查長對話是否需要拆分
- 後續任務分段處理
```

---

## 範例：趨勢報告（週/月）

```markdown
📈 Token 趨勢報告 - 2026-02-16

### 📊 本週累計
| 週期 | 總量 | 變化 |
|------|------|------|
| 本週 | 320K tokens | - |
| 上週 | 280K tokens | +14% |

### 🔥 關注重點
使用量微幅上升，仍在合理範圍

### 💡 建議
- 持續觀察即可
- 如有大型任務可考慮排程
```

---

## 備註

- 日期格式：YYYY-MM-DD（台北時區）
- 數字千分位：123,456
- 貨幣可選欄位（需計算成本）
- Markdown 表格相容 Telegram
